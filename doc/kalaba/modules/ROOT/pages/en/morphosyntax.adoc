== Rules per category

Each top-level key (e.g. `NP`) defines a rule with two sides:

* `Source` — parse and translate from French
* `Destination` — validate invented-language output

=== Example (`examples/data/`)

include::partial$morphosyntax/np-rule-block.adoc[]

* `phrases` — sequences of lexical or non-terminal categories
* `agreements` — feature constraints (`Genre,Nombre` or `Trait=value`)
* `percolations` — features attached to the parent node
* `translations` — 0-based constituent index order for translation output

The three variants cover `D NOM`, `D ADJ NOM` (prenominal adjective) and `D NOM ADJ`
(postnominal adjective). Both French adjective positions are reordered into a single
`NOM ADJ D` pattern: the difference is carried by `translations` (`[ 2, 1, 0 ]` versus
`[ 1, 2, 0 ]`).

`Destination` agreements are not decorative: they are merged into the source rule (see
`Production.update`) and therefore constrain the translation. Here `Genre,Nombre`
forces the determiner and the adjective to take the *inherent* gender of the Kalaba
noun, which is not the gender of the French one.

WARNING: Each list (`phrases`, `agreements`, `percolations`, `translations`) must have the same length for a given rule variant.

=== Full sentences (`examples/data3/`)

`examples/data3/` goes one level up: the start symbol is `S`, and it calls the `NP`
and `PP` rules. A rule can therefore refer to another rule, not only to lexical
categories.

include::partial$morphosyntax/s-rule-block.adoc[]

Three mechanisms come with it.

**Valence lives in the lexicon.** Every verb carries a `Val` feature (`intr`, `tdir`,
`tind`, `ditr`, see xref:en/stems.adoc[]). A rule does not describe "a verb" but "a
verb of that valence": `"les enfants mangent"` has no parse, for want of an object.

**Agreements are given constituent by constituent.** An agreement string split on `;`
holds one segment per constituent, and an empty segment constrains nothing:

[cols="1,3"]
|===
| String | Effect on `[ NP, V, NP ]`

| `"Genre,Nombre"` | broadcast: all three constituents agree (what `NP` does)
| `"Nombre;Nombre,Val=tdir;"` | subject and verb agree in number, the verb is direct transitive, the object is free
|===

WARNING: A string split on `;` must have exactly one segment per constituent, otherwise it is rejected (`FeatureMixin.broadcast`).

**Translations nest.** A rule's `translation` feature collects those of its
constituents; when a constituent is itself a nonterminal the result is a tuple of
tuples, which the parser flattens before joining the words.

The `Destination` side sends the verb to the end of the clause (Kalaba is SOV, French
SVO), and the preposition becomes a postposition:

include::partial$morphosyntax/pp-rule-block.adoc[]

[TIP]
Feature string syntax
====
* `Genre,Nombre` — propagate lexical features
* `Nombre=du` — fixed value
* `;` — constituent separator: one segment per element of `phrases`
* an empty segment — no constraint on that constituent
====

== Destination

The `Destination` side has no `translations` field. It is used in the parser
validation phase (see xref:en/parsing-pipeline.adoc[]).
