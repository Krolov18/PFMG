= Gloses.yaml

`Gloses.yaml` declares morphological features per syntactic category, separately for
the source language (French) and the destination (invented language).

Full reference: `examples/data/Gloses.yaml`.

== Structure per category

Each top-level key is a category (`D`, `NOM`, …) with:

* `source` — licensed attribute values on the French side
* `destination` — attribute values on the invented-language side
* `alignments` — mapping between source and destination features

=== Determiners (`D`)

include::partial$gloses/d-glose-block.adoc[]

* `source.Genre` / `Nombre` — French paradigm features
* `destination` — may add values (e.g. neuter `n`)
* `alignments` — maps `Nombre=pl` to `Nombre=du` or `Nombre=pl` on the destination side

=== Adjectives (`ADJ`)

include::partial$gloses/adj-glose-block.adoc[]

* Like the determiner, the adjective has no inherent destination gender: it takes the
  noun's through the agreement declared in `MorphoSyntax.yaml`

=== Nouns (`NOM`)

include::partial$gloses/nom-glose-block.adoc[]

* `destination.Cf` — inflection class (`n1`, `n2`) used in `Blocks.yaml` and
  `Stems.yaml`

NOTE: Alignments let you realize richer destination paradigms than the source without
duplicating every form by hand.

=== Non-inflectional features

A feature declared in `source` but never used in `Blocks.yaml` realizes no form: it
only serves syntactic agreement. `Val` (verbal valence) in `examples/data3/` is one,
declared on the source side only.

CAUTION: Every category must provide `source`, `destination` and `alignments`. A
single category without `alignments` makes the whole file fall back to unconstrained
gloses (`StraightPos2Sigmas`).
