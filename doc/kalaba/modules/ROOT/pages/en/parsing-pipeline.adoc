= Parsing pipeline

The `KParser` loads a grammar directory (all five YAML files) and runs two phases:
translation then validation.

== Loading

[source,python]
----
from pfmg.parsing.parser import KParser

parser = KParser.from_yaml("examples/data")
----

`KParser.from_yaml()`:

. Builds a `Lexicon` from `Gloses`, `Blocks`, `Stems`, `Phonology`
. Loads `KGrammar` from `MorphoSyntax.yaml` (translator and validator grammars)

== Phase 1 — Translation

The **translator** grammar uses `Source` rules and the `translations` field in
`MorphoSyntax.yaml`. It produces invented-language strings from French input.

== Phase 2 — Validation

The **validator** grammar uses `Destination` rules (without `translations`) to keep
valid analyses only.

== Terminals and lexical ambiguity

The terminals of the generated grammars are the **surface forms**: the translator
grammar is keyed on French, the validator one on the invented language
(`LexicalGrammarExporter`). A spelling shared by several paradigm cells therefore
yields several lexical productions, and the chart parser explores them together: a
sentence takes **one single Earley parse**, however ambiguous it is morphologically.
That ambiguity is carried by the features, not by splitting the input.

`Parser` is thus reduced to tokenizing the sentence and checking that every token is a
realized form (`Lexicon.knows`); an unknown word is reported at once rather than
yielding no analysis.

NOTE: The NLTK grammar reader has no escape inside literals. A form holding an
apostrophe is written with double quotes; a form holding both kinds of quotes is
rejected at export time.

----

== Command-line interface

[source,bash]
----
uv run python -m pfmg.parsing.main parsing examples/data "des garçons"
uv run python -m pfmg.parsing.main parsing examples/data "des garçons" -k all
----

* `-k first` (default) — keep the first analysis
* `-k all` — all analyses (morphological and syntactic ambiguity; see
  `examples/execution_grammaire.ipynb`)

== Feature strings in MorphoSyntax

`agreements` and `percolations` use feature strings:

* `Genre,Nombre` — features propagated from the lexicon
* `Nombre=du` — fixed value
* `;` — constituent separator: one segment per element of `phrases`, an empty
  segment constraining nothing (`FeatureReader` in
  `pfmg/utils/features/feature_reader.py`)

== Quoted literals

In `examples/data2/MorphoSyntax.yaml`, a constituent can be a literal:

[source,yaml]
----
phrases:
  - [ "D", "'deux'", "NOM" ]
----

Single quotes inside double quotes are required so the tokenizer keeps the token
as-is.
