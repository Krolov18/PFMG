= Pipeline de parsing

Le parseur `KParser` charge un répertoire de grammaire (les cinq fichiers YAML) et
exécute deux phases : traduction puis validation.

== Chargement

[source,python]
----
from pfmg.parsing.parser import KParser

parser = KParser.from_yaml("examples/data")
----

`KParser.from_yaml()` :

. Construit un `Lexicon` depuis `Gloses`, `Blocks`, `Stems`, `Phonology`
. Charge `KGrammar` depuis `MorphoSyntax.yaml` (grammaires translator et validator)

== Phase 1 — Traduction

La grammaire **translator** utilise les règles `Source` et le champ `translations`
de `MorphoSyntax.yaml`. Elle produit des chaînes en langue inventée à partir du
français.

== Phase 2 — Validation

La grammaire **validator** utilise les règles `Destination` (sans `translations`) pour
filtrer les analyses valides.

== Terminaux et ambiguïté lexicale

Les terminaux des grammaires générées sont les **formes de surface** : la grammaire
translator est indexée sur le français, la validator sur la langue inventée
(`LexicalGrammarExporter`). Une orthographe portée par plusieurs cellules de paradigme
produit donc plusieurs productions lexicales, et le chart parser les explore ensemble :
une phrase donne **une seule analyse Earley**, quelle que soit son ambiguïté
morphologique. Celle-ci est portée par les traits, pas par le découpage de l'entrée.

Le `Parser` se limite donc à découper la phrase et à vérifier que chaque token est bien
une forme réalisée (`Lexicon.knows`) ; un mot inconnu est signalé immédiatement plutôt
que de produire une absence d'analyse.

NOTE: Le lecteur de grammaire NLTK n'a pas d'échappement dans les littéraux. Une forme
contenant une apostrophe est écrite entre guillemets doubles ; une forme contenant les
deux types de guillemets est refusée à l'export.

----

== Interface en ligne de commande

[source,bash]
----
uv run python -m pfmg.parsing.main parsing examples/data "des garçons"
uv run python -m pfmg.parsing.main parsing examples/data "des garçons" -k all
----

* `-k first` (défaut) — première analyse retenue
* `-k all` — toutes les analyses (ambiguïté morphologique et syntaxique ; voir
  `examples/execution_grammaire.ipynb`)

== Syntaxe des traits dans MorphoSyntax

Les champs `agreements` et `percolations` utilisent des chaînes de traits :

* `Genre,Nombre` — traits propagés depuis le lexique
* `Nombre=du` — valeur fixe
* `;` — séparateur de constituants : un segment par élément de `phrases`, un
  segment vide ne contraignant rien (`FeatureReader` dans
  `pfmg/utils/features/feature_reader.py`)

== Littéraux entre quotes

Dans `examples/data2/MorphoSyntax.yaml`, un constituant peut être un littéral :

[source,yaml]
----
phrases:
  - [ "D", "'deux'", "NOM" ]
----

Les quotes simples à l'intérieur des doubles quotes sont requises pour que le token
soit reconnu tel quel par le parseur.
